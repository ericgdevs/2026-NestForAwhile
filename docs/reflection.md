# Team reflection: Team Sandwich (Eric Good, Caden Wondell)

We planned once, in a single conversation with all the direction documents loaded: the problem case, the kick-off slides, the judging criteria and our research. From that we wrote a Spec Kit constitution, spec, plan and tasks, which gave us a shared contract so the two of us could build the backend and frontend in parallel on separate branches. We gave our AI coding agent small, scoped prompts and read every report before anything was committed. The rules-first design mattered most: deterministic rules decide what is safe and the model only writes recipes from a shortlist, so we never had to trust the model on safety. Our evaluation harness turned "it seems fine" into numbers. Across 20 synthetic cases we saw 0 safety violations after the guard, and the fallback rate on normal cases dropped from 35.7% to 14.3% once we fixed the prompt and the guard.

The hard parts were mostly process. Agents sometimes ignored instructions, for example by committing when told not to, and parallel agents built a duplicate AI layer that we had to merge into one. Merges also dropped rows from our decisions and AI usage logs, and we restored them by hand. Some bugs only appeared on a live preview: a missing household member after seeding, deep links returning 404, and environment variable problems. Testing on real phones and the live preview mattered as much as writing code: QA findings about the camera, recommendations and recipe fallbacks became the prompts that fixed them. Next time we would set up the deploy and a preview environment on day one, give one person ownership of the AI layer, and write the evaluation earlier. Human review stayed essential throughout; the AI sped up the typing, but we still had to decide, check and test.
